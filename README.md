# Профиль маршрута

Приложение строит CSV маршрута, показывает карту и графики, рассчитывает движение условного дизельного грузовика.

## Запуск в Windows

Установите Python 3.10 или новее. Распакуйте архив целиком, запустите START.bat. Оставьте окно сервера открытым. После обновления остановите старый сервер и запустите новый. В шапке новой версии есть отметка R2.

## Создание маршрута

Откройте «Создать маршрут». Нажимайте на карту в порядке движения: первая точка — старт, последняя — финиш, все остальные — промежуточные. Маркеры можно перетаскивать. Под картой можно удалить точку или изменить порядок стрелками. Допускается от 2 до 50 точек; соседние точки должны различаться минимум на метр. Диапазон координат проверяется сервером, доступность автомобильного проезда — сервисом openrouteservice. Выбор точки не гарантирует наличие дороги в ней.

Введите API-ключ и окно сглаживания, нажмите «Сгенерировать CSV». После получения результата нажмите «Сохранить CSV как…». Edge и Chrome позволяют выбрать папку и имя. Откройте сохранённый CSV кнопкой «Открыть маршрут». Интернет нужен для фоновой карты и построения маршрута. Ключ не сохраняется; при закрытии окна поле очищается.

## Расчёт движения

Остался один метод: разгон перед подъёмом, снижение мощности на подъёме и накат либо тяга на спуске. Укажите массы и параметры грузовика, выберите исходный или сглаженный рельеф и нажмите «Рассчитать скорость». Программа подбирает крейсерскую скорость, дистанцию разгона, запас скорости и мощность у вершины по общему расходу. Максимальная скорость по умолчанию 120 км/ч. Заданная средняя скорость ограничивает время поездки сверху. Минимум топлива гарантируется только среди проверенных вариантов.

Проценты выполнения приблизительные, рассчитываются по длительности ожидания. 100% появляется после ответа сервера. После успешного расчёта доступны движение автомобиля, графики и экспорт. Множитель анимации меняет только скорость просмотра.

## Как устроен код

- start.py — локальный сервер, проверка запросов, вызов API и расчёта.
- route_to_csv.py — получение и обработка высот, сглаживание и CSV.
- vehicle_physics.py — параметры грузовика, сетка дороги и доступная мощность двигателя.
- terrain_strategy.py — движение по шагам времени и поиск экономичных настроек.
- generator.js — карта выбора точек, генерация и сохранение маршрута.
- truck.js — параметры и результаты расчёта, прогресс и экспорт.
- data.js — чтение CSV и проверка данных.
- app.js — основная карта, график и анимация.
- analysis.js — отдельная страница графиков.
- route-controls.js — управление положением автомобиля.

Leaflet находится в vendor; его лицензия сохранена. Расход и характеристики двигателя учебные и требуют калибровки для реального автомобиля.

## Пропуски навигации (G1)

Откройте исходный CSV обычной кнопкой «Открыть маршрут». В верхней панели «Пропуски навигации» задайте средний интервал без потерь, среднюю длину пропуска и число эксперимента. Нажмите «Создать файл 2 с пропусками», затем «Сохранить файл 2». Имя по умолчанию — 2.csv. Исходный файл не перезаписывается.

Оба случайных значения равномерно выбираются от 50% до 150% введённого значения. Первый интервал отсчитывается от старта, следующие — от конца предыдущего пропуска. Удаляются точки, попавшие внутрь интервала по distance_from_start_m. Начальная и конечная точки сохраняются. В короткий пропуск может не попасть ни одной точки. Количество удалённых строк показывается после обработки. Одинаковое число эксперимента, настройки и исходный файл дают одинаковый результат.

Сохранившиеся значения полей и идентификаторы не пересчитываются, в том числе расстояние от старта, высоты, уклоны и segment_length_m. Поэтому segment_length_m после удаления относится к предыдущей исходной точке, которая могла быть удалена. Это имитация потери записей, а не восстановление навигации. Формат записи CSV нормализуется: запятая, кавычки, UTF-8 BOM.

Файл 1 показан бирюзовым, файл 2 — оранжевым. Ранее сохранённый файл 2 открывается в верхней панели восстановления. Если точки сопоставляются с файлом 1 по ID и координатам, удалённые участки показаны разрывами. Иначе файл 2 отображается обычной линией с пояснением. Флажки независимо скрывают линии. До восстановления график показывает загруженный исходник. Расчёт движения доступен только по восстановленному файлу 3. Загрузка нового файла 1 очищает прежнее сравнение.

Проверка алгоритма пропусков: node tests/test_gaps.cjs. Библиотеки Node не требуются.

## Восстановление повреждённого маршрута (R1)

В верхней панели «Восстановление маршрута · файл 3» выберите повреждённый CSV. Загружать файл 1 не нужно. Укажите порог скачка, окно сглаживания и API-ключ, затем нажмите «Восстановить файл 2». Полученный маршрут появится фиолетовым, наблюдения файла 2 — оранжевыми точками. Их можно скрывать независимо. Сохраните результат как 3.csv. После восстановления файл 3 автоматически выбран для графиков и расчёта скорости. Нажмите «Рассчитать скорость» в разделе «Транспорт».

Порог по умолчанию 1 км. Для каждой пары соседних наблюдений считаем расстояние по координатам. Если оно больше порога, запрашиваем у openrouteservice автомобильный путь между двумя граничными точками. Используем единственный предложенный API маршрут, не предлагаем выбор пользователю. Запросы выполняются последовательно для всех обнаруженных скачков. Программного ограничения на количество запросов за восстановление нет. Квоты самого API продолжают действовать.

Алгоритм recovery.py получает только текст файла 2, порог, окно сглаживания и функцию запроса API. Он не открывает файлы и не обращается к исходному маршруту приложения. Номера точек, прежние расстояния и уклоны в файле 2 игнорируются при обнаружении и восстановлении. Файл 1 и сравнение с ним не участвуют в восстановлении. Чтение поля загрузки и запрос выполняются отдельным модулем recovery.js.

Без временных меток «скачок» означает большое расстояние, а не измеренную скорость ТС. Порог может принять редкие исходные точки за пропуски и пропустить маленькие потери или петлю, края которой находятся рядом. Восстановленный путь — предположение API, а не доказательство совпадения с исходной дорогой.

Все наблюдаемые координаты и исходные высоты файла 2 сохраняются. Новые точки получают point_source=api, наблюдаемые — observed. recovery_gap задаёт номер восстановленного участка для добавленных точек, 0 — для наблюдаемых. Point_id формируется заново только для результата. Расстояния, сегменты, уклоны и сглаженные высоты пересчитываются по новой геометрии. Остальные произвольные столбцы исходного CSV не переносятся.

API может привязать граничную координату к ближайшей дороге. Смещение более 100 м вызывает отказ для этого скачка. При меньшем смещении сохраняются и наблюдаемая точка, и точка дороги (если они различаются хотя бы на 0,1 м); между ними остаётся короткое соединение. Это не гарантия проезжаемости такого соединения. Ошибка хотя бы одного API-запроса прекращает восстановление без выдачи успешного файла 3; уже выполненные запросы могут учитываться квотой сервиса.

API-ключ после завершения восстановления очищается из поля. Маршрут и ключ не сохраняются сервером на диск. Для проверок без сети: python tests/test_recovery.py. Реальный API требует собственного ключа и интернет-соединения.

## Большая карта и расчёт по восстановленным данным (R2)

Основная карта имеет высоту 80% окна, минимум 650 пикселей (на узком экране минимум 480 пикселей). Вся страница прокручивается; верхние панели и транспорт больше не ограничены внутренней прокруткой.

После успешного восстановления результат автоматически становится активным маршрутом графиков и модели. Прежний расчёт аннулируется. Расчёт скорости запускается кнопкой в разделе «Транспорт» и использует расстояния и выбранный профиль высот из восстановленного результата. Файл 1 используется только для визуального сравнения. Изменение настроек восстановления или повреждённого файла блокирует новый расчёт до восстановления.

Сохранённый файл 3 можно открыть обычной кнопкой: он распознаётся по столбцам point_source и recovery_gap. Это обозначение формата результата, не криптографическая проверка происхождения файла. Обычные файлы 1 и 2 без этих столбцов не допускаются к расчёту скорости.

## Метки восстановленных участков (R3)

В файле 3 добавлены поля:
- point_source: observed — сохранённая точка файла 2, api — добавленная точка сервиса.
- is_recovered: 1 для добавленной точки, иначе 0.
- recovery_gap: номер пропуска для добавленной точки, 0 для наблюдаемой.
- segment_recovered: 1, если отрезок от предыдущей строки к текущей относится к восстановленному пропуску, иначе 0.
- segment_recovery_gap: номер этого пропуска, иначе 0.

Отрезок, который заканчивается сохранившейся точкой после пропуска, также помечен восстановленным. При этом сама сохранившаяся точка остаётся observed. После восстановления такие отрезки видны красным пунктиром поверх фиолетового маршрута. Большая карта, прокрутка страницы и расчёт скорости по файлу 3 сохранены.


## R5 — автоматическая стратегия
Из формы удалены порог рельефа, время реакции, крейсерская скорость, дистанция разгона и доля мощности у вершины. Порог всегда 0,002 (0,2%), реакция всегда 8 с. Автоматический поиск не принимает пользовательские значения остальных удалённых настроек: он подбирает их внутри модели, проверяя движение по всему маршруту и выбирая наименьший расход среди найденных допустимых вариантов. Дистанция разгона — параметр ограниченного поиска, а не гарантия нахождения любого физически возможного решения. Скорость во всех расчётных точках, включая вершины, не должна быть ниже vmin; прежний допуск 0,3 км/ч убран. При недостаточной мощности вариант отклоняется, скорость искусственно не поднимается. Глобальный минимум расхода не гарантируется.
